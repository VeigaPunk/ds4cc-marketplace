killed · memory substrate

Honcho — the worst suck we have measured

KILLEDnot Phase-0not default memory

Honcho is the most elaborate way we have ever seen to not get durable, mission-scoped recall. Marketing: “statefulness solved,” “memory that reasons,” MCP for every client. Reality after stress + reaudit: probabilistic dialectic chat as “read path”, no real user metadata for structured axes, session semantics that fight multi-mission authority, and a design that begs you to client-patch around missing primitives.

That is peak suck: not “a bit slow,” but architecturally wrong for a judge stack. We did the primary-source work (schema, deriver, chat tool-loop). Verdict: R0 — no Honcho. SQLite-authoritative findings stay. FTS5 before you even think of reopening. If a tool needs you to rewrite your stack to host it, the tool is the bug.

  • Suck factor: max — worst “memory product” fit we tried for xbreed/xbgst
  • Use instead: local SQLite + scribe reports
  • Evidence: honcho-reaudit-closure-2026-04-18 (marketplace plugin docs)
  • Reopen: only named upstream schema/API changes — not a blog post

killed · toolchain · enshittified PATH

mise — the most enshittified Node manager ever shipped

KILLEDnot fnmPATH occupancy

Imagine recommending mise for Node. XDDDD. It is not a version manager. It is a polyglot runtime religion wearing nvm’s coat: shims, activation hooks, plugin galaxies, “one tool to own PATH.” The job was pin Node. The product is occupy the shell.

Elegant shit: a kitchen sink that breaks everything it pretends to unify. Mystery node. Agent jobs that worked until the shim. CI that inherited a worldview. fnm does the one job — Fast Node Manager, no runtime theocracy. The glaze is earned: fnm multishell — eval "$(fnm env --shell bash)", fnm exec --using … — per-shell Node, no global shim occupation. Tools adapt to us. mise wants the reverse. Kill it as default. Do not “just try asdf again with a new name.”

  • Suck factor: peak — most enshittified Node manager in the drawer
  • Failure mode: PATH/shim occupancy, not “slow installs”
  • Use instead: fnm multishell + .node-version
  • Reopen: Node-only, no shims, one-command PATH restore — not “but Python too”
