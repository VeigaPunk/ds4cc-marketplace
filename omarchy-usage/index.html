Omarchy Usage Tray

One bar chip for 14 AI usage meters — Codex, Anthropic, Cursor, Grok, Kimi, Devin (two accounts), Google, Token Plan, Z.ai, OpenCode Go, Command Code, Charm Hyper, and Inception. Every meter comes from omp usage --json, so the native CLIs are not required. A provider that cannot show a real number drops out of the cycle instead of rendering an invented zero.

install

Install on Omarchy

Needs Python 3 and omp on PATH, signed in to the providers you want metered. No sudo.

Quattro bar (Omarchy plugin)

omarchy plugin add https://github.com/VeigaPunk/omarchy-usage-tray.git --enable

The plugin ships its own refresh service, so there is no installer and no systemd timer.

Waybar

git clone https://github.com/VeigaPunk/omarchy-usage-tray.git && cd omarchy-usage-tray && ./install.sh

Backs up and edits ~/.config/waybar/, links ~/.local/bin/ai-usage, enables the ai-usage.timer user unit, and floats the TUI on Hyprland. Never writes under ~/.local/share/omarchy/. Re-run ./install.sh to update. Remove with ./uninstall.sh or omarchy plugin remove io.github.veigapunk.usage-tray.

implementation

How it works

  1. Probe. ai-usage refresh runs omp usage --provider <id> --json for each provider on the roster, serially. Inception has no usage API, so its meter is a ledger of the tokens OMP spent, summed from OMP's session transcripts.
  2. Schedule. Every 5 minutes: on Quattro, the plugin's Service.qml runs the refresh once for all monitors and skips a tick rather than overlapping a slow run; on Waybar, the ai-usage.timer systemd user unit runs it.
  3. Cache. Results land in ~/.cache/ai-usage/status.json. A provider that fails keeps its last good meters and shows the reason; data older than 20 minutes is marked stale.
  4. Render. The chip only reads the cache (ai-usage waybar) — it never probes. It re-renders after each refresh and every 60 seconds; on Waybar, clicks and scrolls signal it to re-render immediately.

Missing data is never invented: a window the provider did not answer shows —, and a total is withheld rather than understated when one account answers nothing. ai-usage tui opens the full dashboard.

gestures

Bar clicks

GestureAction
Left-clickNext provider
ScrollCycle providers
Right-clickNext identity, where a provider has one to switch

Right-click does real work for two providers. Token Plan runs token-plan-swap toggle, which switches the active key slot and rewrites ~/.bailian/config.json, so Codex and xask follow the new route. Kimi runs both OAuth accounts through omp auth-gateway, which balances sessions on its own, so right-click just reports that state. Everywhere else it is a no-op, because those credentials live in OMP's auth store with no local file to flip.

configuration

Provider roster

By default all 14 providers are probed and cycled. To meter only what is authed on this machine, list provider ids one per line in ~/.config/ai-usage/providers, or set AI_USAGE_PROVIDERS="codex kimi". An unknown id prints one warning and is skipped. Knobs such as the Token Plan pool size or the Charm Hyper low-credit alarm live in ~/.config/ai-usage/env, which the installer never overwrites.
